# Runwall adoption signals

Count demonstrated use separately from GitHub stars. Do not infer an install
or repeat use from a clone, view, download, or star. Runwall has no usage
telemetry in this increment.

| Signal | Count when | Evidence source |
|---|---|---|
| Successful installs | A user reports a completed install | Opt-in first-run issue or direct feedback |
| Demo completions | A user reports `Demo PASS` and both expected routes | Opt-in first-run issue or direct feedback |
| External issues | An issue from someone outside the owner account describes a reproducible defect or question | GitHub issue URL |
| Repeat users | The same user provides a second dated use report | Linked, dated feedback records |
| Contributors | A non-owner change is merged | Merged PR URL |
| Stars | Current GitHub repository count | GitHub repository page |

Record weekly counts with links to the supporting reports. Start unknown values
as **unknown**, not zero. Keep issue reports free of credentials, local paths,
private customer data, and raw ledger payloads. Use the
[first-run issue template](https://github.com/dburt-proex/Runwall/issues/new?template=first-run.md) to reduce
reporting friction. No user report or permission is implied by a CI run.
